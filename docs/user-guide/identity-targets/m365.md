# Microsoft 365

Scope Microsoft 365 on the same tenant as Entra — provide the Graph scopes you authorize for mailbox/SharePoint/Teams access.

> [!NOTE] At a glance
> - **`kind`:** `m365`.
> - **You provide:** the tenant id (shared with the [Entra ID](./entra-id.md) target) and credentials carrying the Graph scopes you authorize.
> - **Capabilities:** mailbox / SharePoint / OneDrive / Teams access, eDiscovery & app-registration abuse, AADInternals / Golden SAML.
> - **Same tenant as Entra:** M365 and Entra ID share one tenant — scope both to cover directory **and** data.

> [!TIP] New here?
> Start with the [Identity overview](./overview.md) for the provider matrix and the two safety rails.

## What you provide

| Field | Required | Notes |
|---|---|---|
| **Tenant ID** | yes | The same tenant GUID as your [Entra ID](./entra-id.md) target — the in-scope identifier the tools validate against. |

M365 data-access tests use the Microsoft Graph scopes you authorize — `Mail.Read`, `Sites.Read.All`, `Files.Read.All`, `Team.ReadBasic.All`, etc. Grant **only** the scopes matching the data you've authorized Maestro to reach.

## Add it — the UI flow

Sidebar → **Config** → **Identity Targets** → **Add**.

1. **Provider** → **Microsoft 365**.
2. **Tenant ID** → the same tenant as your Entra ID target.
3. **Verify** → structural config check.
4. **Save**.

> [!NOTE] Under the hood (scope.yml)
> ```yaml
> identity_targets:
>   - id: corp-m365
>     kind: m365
>     tenant_id: "11111111-2222-3333-4444-555555555555"   # same tenant as corp-entra
> ```
> The authorized Graph scopes ride on the credential stored in `config/credentials.yml` under `identity_credentials`.

> [!TIP] Reuse the Entra app registration
> M365 shares the Entra tenant, so the cleanest path is to add the mailbox/SharePoint/Teams Graph scopes you authorize to the same app registration you created for [Entra ID](./entra-id.md) — admin-consenting the extra read scopes — rather than minting a second principal.

## What it does

- **Read-only, runs freely:** mailbox, SharePoint, OneDrive, and Teams enumeration and read access within the authorized scopes; app-registration and eDiscovery enumeration.
- **State-changing (opt-in, pauses for confirmation):** eDiscovery & app-registration abuse, AADInternals operations, Golden SAML forging.

## Safety rails (always on)

- **Account-lockout mandate.** Any user-credential spray honors the `lockout_threshold` on the tenant's identity targets — below threshold, one attempt per user per window, jitter, abort on first lockout; `exclusions` never touched.
- **Non-destructive by default.** Data **reads** within authorized scopes run freely; data-access escalation, eDiscovery abuse, and Golden SAML are gated behind explicit opt-in and pause for confirmation.

## Troubleshooting

> [!WARNING] Mailbox / SharePoint reads return 403
> M365 data scopes are separate from directory-read. Confirm the credential's app registration has the specific Graph **read** scopes you authorized (`Mail.Read`, `Sites.Read.All`, …) and that they've been **admin-consented** — directory-read alone won't reach mailboxes or sites. Also confirm the **Tenant ID** matches the Entra tenant exactly.
